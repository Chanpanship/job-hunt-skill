# Interview prep

## Assets to build once, reuse everywhere
- **Story bank**: 8-12 STAR stories from `profile.md`, each tagged with the
  competencies it covers (conflict, failure, leadership, ambiguity, influence
  without authority, shipping under deadline, disagreeing with a manager). One
  story can cover several tags; aim for coverage, not volume.
- **"Tell me about yourself"**: 90 seconds, three beats — where you are now, the
  arc that got you here, why this role specifically. Rewrite the third beat per
  company.
- **Questions for them**: 5 per company, from real research, none answerable by
  reading the careers page.
- **Comp script**: the walk-away number from `target.md`, the target number, and
  a prepared deflection for "what is your current salary" — many jurisdictions
  bar the question; deflect to expectations either way.

## Loop-specific
- **Coding**: clarify → examples → approach out loud → complexity → code → test
  an edge case. Announce the brute force before optimizing.
- **System design**: requirements and scale numbers → API → data model →
  high-level diagram → bottleneck → one deep dive. Ask what they want to focus
  on rather than guessing.
- **Behavioral**: STAR with a quantified R. Watch the I/we ratio.
- **Domain / case**: structure first, state assumptions, do arithmetic out loud.

## Mocks
Claude can run mock interviews in-session: pick the loop type, stay in role,
interrupt like a real interviewer, then give feedback as
`what worked / what lost points / what to drill`. Score against a rubric, not
vibes. A generous mock is worthless.

## Post-interview
Write a same-day debrief per interview: questions asked, what went badly, what
to drill. This compounds across a search more than any other habit.
